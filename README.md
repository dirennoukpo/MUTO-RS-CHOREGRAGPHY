# MUTO-RS-Choregraphy

## Description
Repository for the MUTO-RS hexapod software stack. The workspace is organized around a ROS 2 control pipeline, a low-level serial hardware layer, a robot description package, and an ONNX-based policy inference node.

The main workspace lives in [muto_ws](muto_ws), which contains the ROS 2 source packages and the usual `build/`, `install/`, and `log/` artifacts generated by Colcon.

## Usage / Examples
Typical build and runtime workflow from the repository root:

```bash
cd muto_ws
colcon build
source install/setup.bash
ros2 launch muto_bringup bringup.launch.py
```

If you need to validate an ONNX model before launch, use:

```bash
python3 src/scripts/check_onnx.py src/muto_description/config/muto_walk_policy.onnx
```

## Technical Notes
- The repository targets ROS 2 and assumes a Colcon-based workspace.
- The bringup stack depends on `muto_description` for the URDF and controller configuration.
- `muto_policy` depends on ONNX Runtime and must be built in the same workspace unless you provide a compatible install environment.
